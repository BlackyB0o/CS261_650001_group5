# CarryHub — ระบบรับฝากซื้อและรับหิ้วภายในมหาวิทยาลัย

## 1. ภาพรวมโครงการ (Project Overview)

CarryHub เป็นเว็บแอปพลิเคชันที่พัฒนาขึ้นเพื่อเชื่อมต่อผู้ที่ต้องการฝากซื้อสิ่งของกับผู้ที่ต้องการรับซื้อและนำสิ่งของไปส่งให้ภายในมหาวิทยาลัย โดยเน้นการฝากซื้ออาหาร เครื่องดื่ม และสิ่งของที่นักศึกษาต้องการในชีวิตประจำวัน

ระบบช่วยให้ผู้ใช้งานสามารถสร้างรอบรับหิ้ว ดูรายการฝากซื้อ รับงาน และติดตามรายละเอียดของรายการได้อย่างเป็นระเบียบผ่านแพลตฟอร์มเดียว

## 2. ปัญหาที่ต้องการแก้ไข (Problem Statement)

การฝากซื้อสิ่งของภายในมหาวิทยาลัยอาจมีปัญหาจากการติดต่อผ่านแชตหรือการบอกต่อกัน ทำให้ข้อมูลกระจัดกระจาย ติดตามสถานะของรายการได้ยาก และอาจเกิดข้อโต้แย้งเกี่ยวกับการส่งมอบสิ่งของหรือการชำระเงิน

CarryHub จึงถูกออกแบบมาเพื่อช่วยจัดการข้อมูลการฝากซื้อและการรับหิ้วให้อยู่ในระบบเดียวกัน เพื่อให้ผู้ฝากซื้อและผู้รับหิ้วสามารถติดต่อและติดตามรายการได้สะดวกขึ้น

### ปัญหาหลักที่ต้องการแก้ไข

- ผู้ฝากซื้อหาคนรับหิ้วได้ยาก
- ข้อมูลการฝากซื้อกระจัดกระจาย
- ติดตามสถานะของรายการได้ไม่สะดวก
- อาจเกิดข้อโต้แย้งเกี่ยวกับการส่งมอบสิ่งของ
- มีความเสี่ยงจากผู้ใช้งานที่ไม่น่าเชื่อถือหรือปัญหาด้านธุรกรรม

## 3. วัตถุประสงค์ของโครงการ (Project Objectives)

1. พัฒนาระบบสำหรับสร้างและดูรอบรับหิ้วภายในมหาวิทยาลัย
2. เปิดให้ผู้ฝากซื้อโพสต์รายการเพื่อหาคนรับหิ้ว
3. เปิดให้ผู้รับหิ้วค้นหาและรับงานฝากซื้อ
4. ช่วยจัดการรายละเอียดและติดตามสถานะของรายการ
5. รองรับการยืนยันการส่งมอบด้วยรูปภาพตามเงื่อนไขของระบบ
6. สนับสนุนการดูแลบัญชีและการจัดการปัญหาที่ถูกรายงานตามขอบเขตที่พัฒนา

## 10. กระบวนการพัฒนาและทำงานร่วมกัน (Development Workflow)

1. วิเคราะห์ความต้องการและจัดทำ Product Backlog
2. เลือก User Story สำหรับแต่ละ Sprint
3. แบ่งหน้าที่และพัฒนาส่วนประกอบตามความรับผิดชอบ
4. บันทึกการเปลี่ยนแปลงด้วย Git Commit
5. Push โค้ดขึ้น GitHub
6. ตรวจสอบและ Merge งานตามกระบวนการของทีม
7. เชื่อมต่อ Frontend, Backend API และ Database
8. ทดสอบการทำงานของแต่ละส่วนและระบบโดยรวม
9. แก้ไขข้อผิดพลาดและทดสอบซ้ำ

## 11. การทดสอบระบบ (Testing)

การทดสอบมีจุดประสงค์เพื่อตรวจสอบว่าระบบทำงานตามความต้องการ และส่วนประกอบต่าง ๆ สามารถทำงานร่วมกันได้อย่างถูกต้อง

| ประเภทการทดสอบ | จุดประสงค์ |
| UI Testing | ตรวจสอบหน้าจอ ปุ่ม แบบฟอร์ม และการเปลี่ยนหน้า |
| API Testing | ตรวจสอบ Request, Response, Status Code และข้อมูลที่ส่งกลับ |
| Validation Testing | ตรวจสอบการรับข้อมูลที่ไม่ครบหรือไม่ถูกต้อง |
| Database Testing | ตรวจสอบการบันทึกและเรียกคืนข้อมูล |
| Integration Testing | ตรวจสอบการทำงานร่วมกันของ Frontend, Backend และ Database |
| End-to-End Testing | ตรวจสอบขั้นตอนการใช้งานตั้งแต่เริ่มต้นจนจบ |

ทีมสามารถใช้ Postman สำหรับทดสอบ API และใช้เว็บเบราว์เซอร์เพื่อตรวจสอบการทำงานของระบบผ่านหน้าจอจริง

ผลการทดสอบต้องอ้างอิงจากการทดสอบที่ดำเนินการจริง ไม่ควรระบุว่าการทดสอบผ่านหากยังไม่ได้ตรวจสอบ

## 12. การจัดการโค้ดและการทำงานร่วมกัน (Version Control)

ทีมใช้ Git และ GitHub เพื่อจัดเก็บโค้ด ติดตามการเปลี่ยนแปลง และสนับสนุนการพัฒนาร่วมกัน

- Repository: พื้นที่จัดเก็บโค้ดและประวัติการพัฒนา
- Branch: แยกพื้นที่ทำงานสำหรับการพัฒนาส่วนต่าง ๆ
- Commit: บันทึกการเปลี่ยนแปลงของโค้ด
- Push: ส่ง Commit จากเครื่องขึ้น GitHub
- Pull: ดึงการเปลี่ยนแปลงจาก Repository
- Merge: รวมการเปลี่ยนแปลงจาก Branch ต่าง ๆ
- Pull Request: ใช้เสนอการเปลี่ยนแปลงเพื่อให้ตรวจสอบก่อนรวมโค้ด
- Conflict Resolution: แก้ไขความขัดแย้งที่เกิดขึ้นระหว่างการรวมโค้ด
